# Project documentation

This directory contains documentation that is useful beyond the code itself. Keep
the root README focused on project orientation and place detailed guidance here as
the website grows.

## Documentation index

| Document                                    | Purpose                                                        |
| ------------------------------------------- | -------------------------------------------------------------- |
| [General design context](design-context.md) | Visual direction, UI language, and moodboard-derived guidance  |
| [Project setup guide](project-setup.md)     | How the initial stack was installed, configured, and organized |
| [UI foundation](ui-foundation.md)           | Theme tokens, typography classes, and reusable controls        |

Add entries to this index when documenting topics such as:

- architecture and data flow;
- animation conventions and accessibility;
- content authoring;
- testing strategy;
- deployment and environment configuration; and
- significant technical decisions.

## Conventions

- Use lowercase kebab-case filenames, for example `animation-guidelines.md`.
- Give each document a clear owner or subject rather than duplicating code comments.
- Record why a significant decision was made, not only what was implemented.
- Update or remove documentation when the corresponding behavior changes.
